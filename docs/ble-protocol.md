# BLE 图片协议 v1

目标：ESP32-S3 + GDEM042F86，400×300，2bpp，30,000 字节；00 黑、01 白、10 黄、11 红；逐行高位像素优先。多字节字段均为小端，无文本/Base64 包装。IEEE CRC32（多项式 0xEDB88320，初值与最终异或 0xFFFFFFFF）；`123456789` 校验值 0xCBF43926。

广播名称 `EPaperFrame`，主广播包含服务 UUID，扫描响应包含名称。最多一个连接。原型不做绑定/配对授权，附近客户端可连接；生产化需添加物理授权窗口与设备绑定。

| 特征 | UUID | 操作 |
|---|---|---|
| 服务 | `f0e10000-9c7d-4f2b-a6c8-61d3e5b74001` | Primary |
| Info | `f0e10001-9c7d-4f2b-a6c8-61d3e5b74001` | Read |
| Control | `f0e10002-9c7d-4f2b-a6c8-61d3e5b74001` | Write with response |
| Data | `f0e10003-9c7d-4f2b-a6c8-61d3e5b74001` | Write with response |
| Status | `f0e10004-9c7d-4f2b-a6c8-61d3e5b74001` | Read / Notify |

## Info（16 字节）

| 偏移 | 类型 | 含义 |
|---|---|---|
| 0 | u8 | 协议版本 1 |
| 1 | u8 | 颜色数 4 |
| 2 | u16 | 宽 400 |
| 4 | u16 | 高 300 |
| 6 | u32 | 帧长 30000 |
| 10 | u16 | Data 最大写入长度，包含 4 字节偏移；min(ATT_MTU−3,244) |
| 12 | u8 | 支持模式位图：bit0 全刷，bit1 快刷 |
| 13 | 3 bytes | 保留 0 |

设备建议 MTU 247，实际由连接协商决定；客户端必须读取 Info，不假设 244。ATT MTU 23 时每个 Data 写入最多包含 16 个图像字节。第一版采用逐包带响应写入保证顺序，未使用窗口化高速传输。

## Control

BEGIN：15 字节，`op:u8=1, version:u8=1, job_id:u32, length:u32=30000, crc32:u32, mode:u8`。job_id 必须非零；mode 0 全刷、1 快刷。成功后独占共享图片任务槽；即使 Wi-Fi/Token 未配置也可接收。忙时拒绝。

COMMIT：6 字节，`op:u8=2, version:u8=1, job_id:u32`。必须为当前会话并已收齐 30,000 字节、CRC32 一致；成功后复制帧并排队。COMMIT 只表示接纳任务，不能当作显示成功。客户端不得因断连或超时自动重发 COMMIT。

ABORT：6 字节，`op:u8=3, version:u8=1, job_id:u32`。仅取消同编号、尚未提交的接收会话；已进入显示队列的任务不能取消。

## Data

`offset:u32 + payload`，总长 5..Info.maxWrite。只接收连续偏移，禁止重复、跳过或越界；错误包不修改已收数据。30 秒没有成功写入或连接断开，会清理未提交会话并释放任务槽。COMMIT 校验失败时会话仍存在，客户端应断开或 ABORT；超时也会清理。

## Status（20 字节）

| 偏移 | 类型 | 含义 |
|---|---|---|
| 0 | u8 | 版本 1 |
| 1 | u8 | 状态：0 idle、1 receiving、2 queued、3 displaying、4 succeeded、5 failed、6 AI busy |
| 2 | u16 | 错误：0 成功、1 包格式、2 忙、3 长度、4 CRC、5 偏移、6 接收超时、7 状态/执行失败 |
| 4 | u32 | BLE job_id；非 BLE 来源为 0 |
| 8 | u32 | 已收字节；queued/displaying/succeeded 为 30000 |
| 12 | u32 | 总长 30000 |
| 16 | u32 | 本次开机成功显示次数（含 AI 来源） |

控制命令与接收超时会触发 Status 更新通知；客户端仍以主动 Read 为准。状态保存在 RAM，重启丢失；后续新任务会覆盖旧结果。BLE 执行错误详情在串口日志中。

## 显示与重连

COMMIT 接纳后，工作任务短暂等待 ATT 响应发送，停止 Wi-Fi，停止 NimBLE 主机并等待主机任务离开事件循环，然后反初始化 NimBLE 和蓝牙控制器。只有确认控制器回到 IDLE，才调用显示驱动；这也覆盖连接事件尚未送达应用层的竞态。保留驱动 8 秒恢复保护和 BUSY 超时。刷新成功/失败后重新初始化 NimBLE/GATT 并恢复广播；终态在恢复广播前写入。停止或重启失败则记录失败，无法确认安全状态时要求重启设备。

网页持有用户已授权的同一 BluetoothDevice 对象，尝试重连并轮询 Status，最多等待约 90 秒；只接受同一 job_id 的 succeeded 且 error=0。页面必须在前台。等待超时并不意味着未显示，手动查询仍核对原设备 ID 与待确认 job_id；另一台相框或后续任务的成功不会被当作本次成功。驱动成功仍需首次联调时目视检查真实画面。
