# BLE 网页换图原型

用户已批准：Android 手机通过自托管 HTTPS 网站选图、裁剪、四色预览，经 BLE 将 30,000 字节面板帧发送到 ESP32-S3 并显示，同时实现网页及设备端接收固件。以后将网页客户端替换为 App，沿用协议。

网站为无第三方运行依赖的静态 HTML/CSS/ES modules，照片只在手机本地处理。目标浏览器 Chrome for Android，部署要求 HTTPS、顶层页面和用户点击授权。提供 Nginx 示例，不擅自部署到用户服务器。

页面以实物相框预览为中心：浅蓝灰工作台、白色画面、黑色文字、红黄四色提示；左侧/移动端上方预览，旁边/下方依次为选图、构图/抖动、蓝牙发送。系统中文无衬线字体；正文左对齐，不使用外部字体或图片资源。用 Canvas 生成本地示例图。显示 BLE 不支持、取消授权、断连和超时的可操作反馈。

图像：居中或自定义位置裁剪为 4:3，缩放 400×300，透明合成白色，可选 Floyd–Steinberg 抖动；颜色编码 00 黑、01 白、10 黄、11 红，每字节高位先行。可导出原始帧，便于离线验证。

协议 v1：一个自定义服务，info/control/data/status 四个特征。控制命令 BEGIN(1)/COMMIT(2)/ABORT(3) 包含版本和非零 job_id。BEGIN 包含 30,000 长度、IEEE CRC32 和刷新模式。DATA 为 uint32 小端偏移加负载，仅接受连续写入，使用带响应写入。INFO 返回尺寸、帧长、按当前 ATT MTU 计算的最大数据写入长度。STATUS 为固定 20 字节，携带版本、阶段、错误、job_id、已收长度、总长、成功显示次数。所有多字节数为小端。

接收会话有 30 秒无数据超时，断连清理尚未提交的会话。校验成功且任务接纳后才刷新；提交后的任务不因断连取消。未知/错误数据不得显示。AI 生图与 BLE 接收共享单任务所有权，BLE 不依赖 Wi-Fi/云 Token 配置。

沿用当前无线静默策略：显示前停止 Wi-Fi，短暂等待提交响应发送，然后停止 NimBLE 主机、确认主机交接并反初始化控制器；控制器确认 IDLE 后才刷新。完成或失败后重建 NimBLE/GATT 并恢复广播，网页针对同一设备重连并读取同一 job_id 的终态。手动恢复也核对设备与任务编号。客户端分别显示传输与刷屏进度，不虚报成功。等待约 90 秒，可手动重连查结果。

边界：不实现账号、云端图库、远程更新、OTA、自动后台重连、持久图片存储或未配对防护；原型在附近可发现，生产化时需增加物理授权/绑定。显示预览是理想四色，不保证实际颜料一致。

验证：C 接收状态机边界测试、JS 图像/协议/传输模拟测试、统一业务调度回归、现有主机回归、ESP-IDF 编译（工具链可用时）、桌面/移动宽度浏览器 QA。蓝牙无线与实屏需要 Android 真机及相框验证，不能以模拟测试代替。
