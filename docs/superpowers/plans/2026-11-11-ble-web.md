# BLE Web Prototype Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. User explicitly requested execution; continue inline without another approval round.

**Goal:** Android HTTPS web page converts a local photo and transmits it over BLE to the actual display firmware.

**Architecture:** Static browser client with independent image conversion, binary protocol and BLE transport modules. A portable C receiver validates frame sessions; a shared firmware worker serializes AI and BLE jobs and a NimBLE adapter handles GATT and radio quiet periods.

**Tech Stack:** ESP-IDF 5.5, C11, NimBLE, browser Canvas/ES modules, Node built-in test runner, Nginx.

**Spec:** docs/superpowers/specs/2026-11-11-ble-web-design.md

**Execution record:** Implemented inline on `codex/ble-web-prototype`; see `docs/ble-web-validation.md` for tests, independent review and server deployment. User explicitly stopped further local firmware compilation after the initial successful build; final firmware compilation/flash/hardware checks are intentionally left to the user. User later supplied and authorized SSH deployment to the IP server; deployed on 8443 to preserve its existing 443 service.

## Global Constraints

- Fixed 400×300 2bpp 30,000-byte frame; 00 black, 01 white, 10 yellow, 11 red.
- BLE transfers work without Wi-Fi or ModelScope credentials.
- One source owns receive/generate/display resources at a time.
- Never display incomplete or checksum-invalid input; release reservations on disconnect and timeout.
- Preserve panel recovery timing and stop radio activity during panel refresh.
- Self-hosted static site; no server-side photo upload, external fonts, or runtime packages.

## Review Focus

- Disconnect during COMMIT: recover by job ID, never blindly retry a display command.
- AI submission during BLE receive and BLE start during AI generation: reject without stealing ownership.
- Malformed/oversized/offset-invalid GATT packets: no overflow and no display.
- Async image changes and disconnects: no stale preview or false success.
- Radio pause/resume failures and reconnects: fail safely and preserve readable terminal state.
